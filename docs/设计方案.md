## 一、P0 地基（必须先做，否则联机必崩）

### P0-1：5 处绕过 dispatch 的直调 → 全部改走 dispatch

**问题**：App.vue 里有 5 处直接 `state.value = gameReducer(...)`，不走 dispatch。联机时这些动作不会发到服务器，导致状态分裂。

| 函数 | 当前问题 | 修改方案 |
|------|----------|----------|
| `onDiceThrow` | 本地算 ROLL_DICE | 改成 `dispatch({ type: 'ROLL_DICE' })` |
| `startStepping` | 本地循环 STEP | 改成 `dispatch({ type: 'STEP' })` |
| `onForkClose` | 本地算 CHOOSE_FORK | 改成 `dispatch({ type: 'CHOSE_FORK', tileId })` |
| `scheduleAI` | 本地跑 aiDecide | 改成 `dispatch(action)` |
| `fastForward` | 调试快进 | 联机模式禁用 |

**dispatch 函数改造**：

```javascript
function dispatch(action) {
  if (netMode.value) {
    // 联机：发给服务器
    socket.emit('action', action)
  } else {
    // 单机：本地算
    const prevMap = lastWalkPaths.value
    state.value = gameReducer(state.value, action)
    // ...动画逻辑...
  }
}
```

### P0-2：isMyTurn 改成基于 myPlayerId

**问题**：`isMyTurn = computed(() => cur.value && !cur.value.isAI)` —— 联机里多人都是非 AI，这个判断失效。

**修改**：

```javascript
// 新增状态
const myPlayerId = ref(null) // 当前玩家在联机的 id

// 修改 isMyTurn
const isMyTurn = computed(() => {
  if (!state.value) return false
  const cur = currentPlayer(state.value)
  if (!cur) return false
  if (netMode.value) {
    return cur.id === myPlayerId.value  // 联机：匹配我的 id
  }
  return !cur.isAI  // 单机：非 AI 就是我
})
```

**波及**：`canThrowDice`、`showForkCard`、`showShop`、`showAuction`、`showCheckin`、`showLottery` 等所有基于 `isMyTurn` 的 computed 自动跟着变。

### P0-3：广播前脱敏（盲拍泄密）

**问题**：整个 state 广播时 `bids` 字段暴露给所有人。

**修改**：广播前对非当前出价方的 state 做浅拷贝，隐藏 `bids`：

```javascript
function broadcastState(room) {
  for (const p of room.players) {
    const gs = room.gameState
    if (gs.phase === 'auction' && gs.pending?.kind === 'auction') {
      // 拍卖中：只给自己看 bids，他人看不到
      const masked = { ...gs, pending: { ...gs.pending, bids: {} } }
      io.to(p.socketId).emit('gameState', { state: masked })
    } else {
      io.to(p.socketId).emit('gameState', { state: gs })
    }
  }
}
```

## 四、Phase 3：游戏同步

### 核心问题：逐格 STEP 同步不能照搬

**问题**：450ms 一次全量广播，8 人房走 8 步 = 8 次全量 state 广播，卡顿+乱序。

**方案**：服务器只广播**关键事件**，前端本地插值动画。

| 事件 | 服务器广播 | 前端处理 |
|------|-----------|---------|
| 掷骰 | `{ type: 'ROLL_DICE', dice, steps }` | 本地播放走格动画 |
| 走完 | `{ type: 'LANDED', pos }` | 显示落地结算 |
| 分岔暂停 | `{ type: 'FORK', options }` | 当前玩家弹选路 |
| 买地/用卡 | `{ type: 'BUY/USE_CARD', ... }` | 更新状态 |

**dispatch 改造**：

```javascript
function dispatch(action) {
  if (netMode.value) {
    socket.emit('action', action) // 发给服务器，等广播回来再更新
    return
  }
  // 单机：本地算
  const prevMap = lastWalkPaths.value
  state.value = gameReducer(state.value, action)
  // 动画逻辑...
}
```

- 所有操作（买地/用卡/交租）完全同步

## 六、Phase 5：上线

### 目标

让朋友通过一个固定链接访问你的游戏服务器，无需公网 IP 或域名备案。

### 方案：Cloudflare Tunnel（推荐）

**优点**：完全免费、固定域名、支持 WebSocket、国内访问快
**前提**：你的电脑开机 + 服务器运行

#### 步骤

**1. 安装 cloudflared**

```bash
# Windows（用 scoop）
scoop install cloudflared

# 或手动下载：
# https://github.com/cloudflare/cloudflared/releases
# 下载 cloudflared-windows-amd64.exe，重命名为 cloudflared.exe
# 放到 PATH 路径下（如 C:\Windows\System32\）
```

**2. 启动游戏服务器**

```bash
cd TOD/projects/monopoly
npm run start
# 服务器在 http://localhost:8080 启动
```

**3. 启动 Cloudflare Tunnel**

```bash
# 新窗口运行
cloudflared tunnel --url http://localhost:8080
```

**4. 获取公网链接**

cloudflared 会输出类似：

```
INF +--------------------------------------------------------------------------------------------+
INF |  Your quick Tunnel has been created! Visit it at (it may take up to 30 seconds to come up):  |
INF |  https://xxxx-xxxx-xxxx.trycloudflare.com                                                         |
INF +--------------------------------------------------------------------------------------------+
```

这个 `https://xxxx.trycloudflare.com` 就是公网链接，分享给好友即可。

**5. 好友访问**

好友打开链接 → 看到首页 → 创建/加入房间 → 玩耍

### 备选方案：ngrok

如果 Cloudflare Tunnel 速度慢，可用 ngrok：

```bash
# 1. 下载 ngrok：https://ngrok.com/download
# 2. 注册免费账号获取 token
ngrok config add-authtoken <YOUR_TOKEN>
# 3. 启动
ngrok http 8080
# 得到 https://xxxx.ngrok-free.app
```

**缺点**：免费版链接每次重启会变。

### 一键启动脚本

创建 `Start-Online.bat`：

```bat
@echo off
cd /d "%~dp0"

echo [1/2] 构建前端...
call npm run build

echo [2/2] 启动服务器...
start "GameServer" cmd /k "cd /d %~dp0 && node server/index.js"
timeout /t 4 /nobreak >NUL

echo [3/3] 启动 Cloudflare Tunnel...
start "Tunnel" cmd /k "cloudflared tunnel --url http://localhost:8080"

echo.
echo 等待 cloudflared 输出公网链接...
echo 复制链接发给好友即可！
pause
```

#### 2. 联机协议（更新后完整规格）

| 事件 | 方向 | 载荷 | 说明 |
|------|------|------|------|
| `createRoom` | C→S | `{playerName, settings, color}` + ack | settings 白名单钳制（回合 5-200 / 资金 1k-1M / 人数 2-8），昵称截 12 字 |
| `joinRoom` | C→S | `{roomId, playerName, color}` + ack | 对局中同名 = 断线重连（ack 带 `rejoined:true`） |
| `ready` | C→S | `{}` + ack | **新增**：非房主切换准备状态 |
| `startGame` | C→S | `{}` + ack | 要求：房主 + ≥2 人 + 全员已准备 |
| `gameStart` | S→C | `{roomId}` | **瘦身**：不再携带 gameState（防手牌泄漏） |
| `gameState` | S→C | `{state, currentPlayerId, myPlayerId}` | 每人一份视角：他人 hand=undefined；拍卖出价阶段 bids 只剩本人 |
| `action` | C→S | `action` + ack | 见下方权限矩阵 |
| `roomUpdate` / `chat` | — | — | 大厅视图 / 聊天，不变 |

**action 权限矩阵（server/rooms.js handleAction）**：

| 场景 | 放行者 | 拒绝 |
|------|--------|------|
| 常规回合操作（ROLL/BUY/END_TURN/USE_CARD/…） | 仅当前回合玩家 | 其他人"还没轮到你" |
| `AUCTION_BID` | `players[pending.turn]`（出价轮转到的玩家，可为非回合玩家） | 其他人 |
| `AUCTION_REVEAL` | 任一玩家（前端限定回合玩家客户端自动触发，避免重复） | roundStep≠1 时 |
| `TRADE_ACCEPT` / `TRADE_REJECT` | 仅 `pending.to`（交易对方） | 发起方自 accept 被拒 |
| `DEBUG_*` | 无人（联机一律拒绝） | 单机模式专用后门 |

#### 3. 走格同步模型（P0-4 / P1-2 / P1-3）

- 服务器在 `ROLL_DICE` **和** `CHOOSE_FORK` 后自动循环 `STEP` 直到稳定态（landed / fork / auction / roll），前端从不发 STEP → 分岔不再死锁。
- `autoStep` 每轮从最新 state 重新取当前玩家（旧代码缓存 structuredClone 前的引用，path 全是起点重复值）。
- 客户端动画：`gameState` 广播到达后对 `walkPath` 做**差量比对**（与单机 dispatch 同一套 `buildMovePaths`），驱动 BoardFx 走格动画 → 联机也有逐格动画，`moveInfo` 协议字段已删除。

#### 4. 掉线托管与重连（P0-6）

- 对局中 disconnect / 主动离开：玩家**保留座位**（`disconnected=true`），gameState 玩家 `isAI=true`。
- `serverNextAction` + 900ms 定时器：轮到掉线玩家（含其拍卖出价、交易响应、卡在分岔）由服务器代打，真人一回来即停。
- 同名 `joinRoom` 重连：座位找回 + `isAI=false` + 立即补发一帧 gameState + 广播 roomUpdate（大厅显示"重连中…"）。
- 全员掉线 → 房间即时清理。

#### 5. 生命周期修复

- **P0-2**：游戏结束 60s 清理改调 `removeRoom()`（旧代码引用未导入的 `rooms` → ReferenceError → 服务器崩溃）。removeRoom 同时清 `_cleanupTimer`/`_aiTimer`。
- **P0-1**：新增 `ready` 协议 + Lobby 准备按钮（此前非房主 ready 永远 false，开始按钮永久禁用 → 联机根本无法开局）。
- **P1-8**：玩家 ID 改房间自增 `playerSeq`（旧 `'p'+length+1` 在退出/再加入时碰撞）。
